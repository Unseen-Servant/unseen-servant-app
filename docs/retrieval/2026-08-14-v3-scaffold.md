## 1. Corpus — `evals/corpus/`, gitignored

Location: `evals/corpus/` inside the app repo, with `evals/corpus/` in `.gitignore` (the manifest lives *beside* it at `evals/corpus.manifest.json` and stays committed — don't let it slide inside the ignored dir). This beats a Desktop path: repo-relative default, no iCloud Desktop-sync eviction risk, one thing to move between machines.

**Worktree gotcha:** the repo uses git worktrees (`.claude/worktrees/…`), and ignored files don't exist in a fresh worktree — evals run from a worktree would find no corpus. `corpus.py` resolves in this order: `LL_EVAL_CORPUS` env var if set → `evals/corpus/` in the current tree → the main checkout's `evals/corpus/` (parent of `git rev-parse --git-common-dir`). That last hop makes worktree runs just work.

Layout is already right: one directory per system, PDF + references side by side. Three touch-ups:

- Delete the duplicate `dnd_srd_52/docs_original/dnd_srd_5.2.1_cc.pdf` (same SHA-256 as the top-level copy — the manifest treats identical hashes as one document).
- Later, non-blocking: add 1–2 homebrew/third-party PDFs with invented proper nouns (the OOV category needs names no embedder saw in training); pay-what-you-want DriveThru titles work.
- Everything here is openly licensed, so the corpus is shareable in principle — but 113 MB doesn't belong in git. The manifest is what's versioned.

`evals/corpus.manifest.json` — seeded with the real hashes, computed 2026-08-14:

Since the corpus is out of git history, it exists only on your disk — so the manifest carries provenance **per artifact**: the PDF and the reference are always two distinct sources (WotC PDF vs a GitHub Markdown repo; OSRIC PDF vs Nik Vinter's SRD site) with different drift risks. The PDF is pinned by its own SHA-256. The reference tree can't practically be hash-pinned file-by-file, so it's pinned two ways: `source` records where it came from (URL, plus a `rev` commit/tag when the origin is a git repo — prefer downloading refs at a pinned rev), and `digest` is an aggregate hash (SHA-256 of the sorted per-file hashes) that the verify script fills on first run and then enforces — reference drift is ground-truth drift, and anchors were verified against *this* snapshot.

## 3. Query schema — paired styles, anchor-graded

```yaml
# evals/retrieval/queries.yaml
- id: q014
  pair: goblin_ac            # keyword+nl forms of one intent share a pair key
  style: keyword             # keyword | nl  → separately scored categories
  category: exact_name       # exact_name | oov_homebrew | table_lookup | prose_rule
                             #   | cross_page | paraphrase_control
  query: "goblin AC"
  doc: srd_5_1               # id from corpus.manifest.json; "any" allowed
  answer_ref: "dnd_srd_51/10_Monsters/Goblin.md"   # canonical source (provenance for review)
  anchors: [["armor class", "ac"], "15", "leather armor"]  # inner list = any-of; all outer must hit
  pages: "302-303"           # optional secondary check, never the primary signal
- id: q015
  pair: goblin_ac
  style: nl
  query: "what armor class does a goblin have?"
  # …same target fields
```

Authoring rules: ~30–40 pairs (60–80 queries); every anchor **verified against the reference file, then against the PDF** (independent re-verification — the old GT was once 30% wrong); OSRIC gets over-weighted (hardest extraction); `paraphrase_control` guards against over-fitting to lexical matching. Grading = all anchors present in the returned chunk+heading text, normalized the way the old scorer already does.

## 6. Conventions

- **Milestones:** one per phase (`v3-phase-0` … `v3-phase-5`) in the app repo; spikes tracked as issues linking their FINDINGS.
- **PRs:** one per ablation rung; the rung's `evals/baselines/*.json` diff is the review body. No baseline, no merge.
- **Baselines naming:** `YYYY-MM-DD-<engine>-<rung>.json|md` (e.g. `2026-09-02-v3-dense-plus-heading.json`).
- **Corpus path:** none needed in the common case (`evals/corpus/` is the default); `LL_EVAL_CORPUS` exists as an override and as the escape hatch for worktrees/CI. The harness errors out with a clear message if the corpus is missing or any hash mismatches.
